# Инвентари Атолл

Магазин автозапчастей и товароучётная система в ChatGPT Sites. Клиентская часть: поиск по артикулу, бренду и названию, склад/под заказ, персональные цены, корзина, заказы, VIN-заявки и баланс. Администратор загружает Excel/CSV-прайсы, ведёт остатки/ячейки/минимумы, оформляет учётные продажи, печатает ценники, формирует закупки и принимает поставки.

## Доступ и данные

Рабочий запуск приватный, для владельца. Авторизацию обслуживает Sites; роли и права проверяются сервером. Товары и операции хранятся в D1, исходные файлы прайсов и фотографии — в R2. Корзина и ключ незавершённой операции хранятся на устройстве для удобства повторного запроса; сервер остаётся источником остатков и сумм.

## Поставщики и прайсы

Администрирование → Поставщики → Добавить поставщика. Название, способ работы (прайс/API/оба), обычный срок доставки, контакты, сайт, ссылки на API и заметки сохраняются в D1. Можно вести 10–15 и больше поставщиков, редактировать карточки и отключать предложения. При переименовании сохраняются ID товаров, связь прайсов и история документов. Отключённый поставщик не участвует в поиске, новых заказах и подборе закупки; данные сохраняются.

В «Прайсах» выберите поставщика из справочника. Обновление затрагивает его каталог. Для поставщика с режимом «только API» загрузка файла недоступна; включите «Прайс и API», если нужны оба способа. Ранее загруженные прайсы прежней версии автоматически связываются со справочником. Адрес API сам по себе не включает обмен: адаптер, авторизация и тестирование на реальном аккаунте настраиваются отдельно.

Администрирование → Уведомления: сохраняемый email для заказов. Начальное значение берётся из runtime-переменной ORDER_NOTIFICATION_EMAIL и переносится в D1 при чтении настроек или выгрузке. Адрес входит в резервную копию данных. Автоматическая отправка требует почтового провайдера и отправителя; она не подключена и не обозначается как работающая.

## ROSSKO

Администрирование → Поставщики → карточка ROSSKO → Подключение по API. «Ключ 1 (KEY1)» и «Ключ 2 (KEY2)» — отдельные поля. Сохранённые значения не возвращаются в браузер; пустое поле сохраняет текущий ключ, новый ключ заменяет только соответствующее значение. «Проверить подключение» проверяет доступ, «Сохранить поставщика» применяет изменения. Новые ключи проверяются перед сохранением; ошибочная проверка сохраняет прежнее подключение.

Единственный адрес: Новониколаевский, ул. Октябрьская, 81А. Самовывоз не используется. Способ доставки выбирается только из разрешённых ROSSKO для этого адреса. Если адрес есть, но ROSSKO не назначил ему доставку, ключи сохраняются, а интерфейс показывает причину недоступности поиска. После настройки у менеджера ROSSKO проверьте подключение и сохраните карточку.

При доступной доставке «Найти» запрашивает текущие цены, остатки, кратность, аналоги и сроки каждого предложения; склады сохраняются отдельными предложениями. Цены клиента учитывают его наценку/скидку. «Интервалы доставки» получает все волны выбранного способа на указанную дату, включая начало, конец и предельное время оформления. Даты/сроки берутся из API, фиксированный срок карточки их не заменяет. Запросы выполняются по нажатию; интервал между запросами — минимум три секунды. Предложения API не отправляют заказ ROSSKO; оформление через менеджера.

Сервер: HTTPS SOAP v2.1 GetCheckoutDetails/GetSearch/GetDeliveryDetails на фиксированном api.rossko.ru. Перенаправления запрещены, ответ ограничен 2 МБ, запрос — 15 сек.; DTD отклоняется. Ключи хранятся в supplier_connections с AES-GCM; SUPPLIER_CREDENTIALS_KEY — серверный секрет Sites. ROSSKO_KEY1/ROSSKO_KEY2 используются только для начальной установки с подписанным запросом; повтор установки не заменяет отредактированные ключи. Секреты не включаются в исходники, ответы API и резервные копии. При переносе данных ключи поставщика вводятся заново, ключ шифрования настраивается отдельно.

## Фотографии товаров

Администрирование → Товары и остатки → Фотографии у нужного товара. Можно загрузить до пяти неподвижных JPEG/PNG/WebP по 3 МБ; предел — 6000 пикселей по стороне и 24 мегапикселя. Первое фото показывается в результатах поиска, нажатие открывает галерею. Нужное фото можно удалить. Изображения привязаны к ID позиции: обновление прайса с тем же артикулом и брендом в том же источнике сохраняет фото. Предложения разных складов/поставщиков имеют свои фотографии. Автоматическая загрузка фото из внешних каталогов не подключена.

Фото включены в полную резервную копию с контрольными суммами и переносятся вместе с данными. Текущий предел полной копии — 64 МБ ZIP / 80 МБ после распаковки; превышение отображается ошибкой, архив не обрезается. Для большего объёма потребуется расширение способа экспорта и восстановления.

## Закупки

Администрирование → Закупки → Потребность. Система вычитает открытые закупки из дефицита и предлагает минимальную цену с достаточным известным наличием. Можно выбрать другое предложение. «Сформировать закупки» создаёт документы по поставщикам. Экспортируйте Excel и после фактического заказа отметьте документ заказанным. Частичная приёмка увеличивает складской остаток и записывает движение. Повторное сохранение той же операции не удваивает количество. Документы и строки сохраняют закупочные цены на момент оформления.

Отправка заказа в API поставщика или по почте пока не подключена. Создание документа закупки не означает отправку внешнему поставщику.

## На компьютере и телефоне

Интерфейс адаптируется к экрану. Внизу страницы есть «Установить приложение». Поддерживающий браузер устанавливает веб-приложение с отдельной иконкой. Для получения актуальных остатков, оформления заказов и работы со складом нужен интернет. Это веб-приложение; отдельные нативные приложения и локальный драйвер кассы ещё не реализованы. Закрытые страницы и API не кешируются Service Worker.

## Перенос

Администрирование → Резервные копии: независимо скачать исходный код ZIP и данные с файлами ZIP. Копия данных содержит manifest.json с SHA-256 каждого файла. Восстановление в Sites выполняется только в пустую базу. Для восстановления на другой сервер:

```bash
python3 scripts/restore-sqlite.py Atoll-backup.zip /absolute/new-directory
```

Команда создаёт обычную inventory.db, папку files и restore-report.json, проверяет суммы, связи и контрольные суммы, сохраняет идентификаторы. Существующий каталог не перезаписывается. Запуск интерфейса/сервера на другом хостинге требует адаптеров авторизации, базы и файлов; сама выгрузка данных не заменяет эти адаптеры. Подробнее: MIGRATION.md.

## Разработка и проверка

Нужны Node.js >=22.13 и зависимости из package.json/pnpm-lock.yaml. Установка, подготовка и публикация через Sites выполняются по инструкции плагина Sites. В исходниках сохранена интеграция сборки sites(). SQL-миграции создаются Drizzle; ранее применённые файлы нельзя переписывать.

```bash
node node_modules/typescript/bin/tsc --noEmit
node scripts/verify-inventory.mjs
node scripts/verify-rossko.mjs
node scripts/export-source.mjs
npm run build
```

Перед сборкой после изменения исходников запустите export-source.mjs: он создаёт server/source-snapshot.json для кнопки выгрузки кода. Экспорт исключает секреты окружения, данные и кеши. Для самостоятельного нового Site замените идентичность проекта штатной регистрацией Sites; не публикуйте чужую копию под прежним project_id.
