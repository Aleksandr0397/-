# Экспорт и перенос

В админке «Резервные копии» есть две независимые выгрузки: исходный код ZIP и данные ZIP. Данные включают текущие/предыдущие прайсы, исходные файлы, товары и остатки, складские ячейки, клиентов и персональные наценки, заказы с сохранёнными ценами, VIN-заявки, подтверждённые пополнения и операции баланса, журнал движения, настройки каталога.

## Восстановление в Sites
1. Развернуть код с новой базой и файловым хранилищем. Сохранить приватный доступ для владельца.
2. Войти через ChatGPT: владелец получает административный кабинет.
3. В «Резервных копиях» выбрать архив и восстановить. База должна быть пустой. Текущая база никогда не очищается этой операцией.
4. Копия проверяется по версии, полям и связям; записи записываются одной транзакцией. Исходные файлы сохраняются под новыми ключами. Роль администратора остаётся у вошедшего владельца; клиенты повторно связываются по подтверждённому email, так как идентификаторы входа различаются между Sites.
5. Проверить количество товаров и заказов, суммы заказов, историю баланса, скачивание исходных прайсов.

## Другой сервер
Исходник содержит интерфейс React/Vinext, серверную бизнес-логику, SQL-миграции и формат выгрузки. Для Cloudflare Workers подключаются D1 и R2. Для VPS или другой платформы нужно заменить драйвер базы, файловое хранилище и вход ChatGPT на подходящие серверу реализации. Файл backup.json пригоден для конвертации в SQLite/PostgreSQL и сохраняет первичные ключи/связи. Тестовый импорт в новую базу не меняет старую.

Native runtime secrets, платёжные ключи и другие учётные данные не входят в выгрузку. Их нужно повторно настроить через безопасные настройки окружения.

## Исходный GitHub
Все три исходных файла GitHub сохранены в legacy-source без изменения. Они не обслуживают новый сайт. Новый код адаптирован для Sites; исходный FastAPI-сервер продолжает оставаться отдельным вариантом запуска.

## Остатки и импорт
Прайс загружается как доступное количество данного источника. Новый прайс заменяет предложения только этого источника. Адрес хранения и минимальный остаток сохраняются для совпадающих артикула и бренда. Если файл содержит физические остатки без учёта уже оформленных резервов, их следует пересчитать перед загрузкой.

## Формат 2 и контрольные суммы

Новые копии добавляют purchase_runs, purchase_orders, purchase_order_items, purchase_receipts и purchase_receipt_items. В manifest.json перечислены backup.json и files/<id прайса> с размером и SHA-256. Перед восстановлением проверяются данные и все исходные файлы. Копии версии 1 остаются допустимыми; если контрольных сумм в старом архиве нет, отчёт не заявляет их проверку.

Выгрузка данных выполняется из одной транзакционно согласованной выборки. Список скачиваемых файлов берётся из этой же выборки. Файлы импортов неизменяемые; новый прайс сохраняется отдельно, поэтому последующее обновление не подменяет байты старой копии. Данные клиентов и ключи авторизации не следует публиковать. Native runtime secrets и auth_user_id исключены из копии.

## Формат 3: поставщики

Текущие копии содержат справочник suppliers, supplier_id в импортах и настройку order_notification_email. Карточки включают режим прайс/API/оба, контакты, сроки и сведения API без ключей. Прайсы связаны со стабильным ID поставщика, а документы сохраняют историческое название. Новые связи и формат проверяются при восстановлении. Копии версий 1 и 2 поддерживаются; прайсы старых копий связываются со справочником при открытии поставщиков. В SQLite старые строки сохраняются с supplier_id=NULL до связывания сервером.

Для первого адреса получателя можно задать runtime-переменную ORDER_NOTIFICATION_EMAIL; последующие изменения сохраняются в D1. Само сохранение адреса не включает отправку писем.

## Проверенное восстановление вне D1

Из архива исходников извлеките scripts/restore-sqlite.py и каталог drizzle. Нужен только Python 3 со стандартным sqlite3:

```bash
python3 scripts/restore-sqlite.py Atoll-backup-2026-10-10.zip /absolute/new-atoll-data
```

Результат: inventory.db, files/ и restore-report.json. Импорт сохраняет идентификаторы и связи, суммы в копейках, остатки, документы закупки и приёмки. Пути file_key пересчитываются под локальные файлы с безопасными именами. До сохранения выполняются проверки SQLite integrity/foreign_key_check, сумм заказов/закупок, количества приёмок и активных прайсов. Существующий каталог никогда не перезаписывается. При повреждённом архиве восстановление останавливается.

В изолированной проверке восстановлены 10 000+ товарных предложений, заказы, баланс, закупки и приёмки. Сравнены бизнес-записи и все байты исходных прайсов. Запуск всего интерфейса на Render/VPS пока не проверен: inventory.db — переносимый набор данных, а серверу требуются адаптеры D1/R2 и новая авторизация. Скрипт не запускает приложение и не подключает кассу или внешние API.
